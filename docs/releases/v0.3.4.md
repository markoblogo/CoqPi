# CoqPi v0.3.4

Compact conversation workspace, faster incremental feedback and dependency fixes.

## Changes

- Three entry modes: Conversation, Recorder and Learning. Compact 640x320 call
  window shows Russian meaning and a larger suggested answer, without dashboard
  navigation. Settings are grouped; technical controls are collapsed.
- Headphones mode separates microphone ME from explicit system OTHER. Shared
  speakerphone mode keeps Space/ME marking. ME is recorded, not analyzed.
- Brief answers stream into the active request. Stop/Reset/context changes hide
  and cancel stale output. Only validated final suggestions are persisted.
- Cancellation also reaches local Ollama fetches and prevents a cancelled call
  from starting another provider attempt.
- Conversation STT waits 500 ms of silence; recorder and separate ME retain
  800 ms. Original-language transcription preserves EN/FR/RU/UK switching.
- Local audio backups and durable transcript checkpoints remain independent of
  assistant/STT success. Review/export/recovery remain available.
- Resolved all 12 known dependency advisories without major-version upgrades;
  see [security maintenance](https://github.com/markoblogo/CoqPi/blob/v0.3.4/docs/audits/2026-10-23/DEPENDENCY_SECURITY.md).
- Corrected the example STT model and refreshed current-mode documentation.

## Verification

`pnpm check` passed: 372 tests, TypeScript, ESLint, repository privacy boundary,
builds and dependency audit (zero known advisories). The cancellation regression
confirms Ollama fetch abortion without a fallback request. No paid provider calls
were needed for this dependency maintenance pass.

Headless UI checks passed for the three modes, compact settings, 400/520px call
layouts, streamed partial output and stale-progress rejection. Recording UI
regressions passed for offline capture, STT failure, OTHER/ME separation and
Stop/Reset. These use synthetic inputs, not a real interview.

The packaged app reported version 0.3.4 and Electron 44.9.3. Real local BlackHole
audio capture without an API key saved a non-silent WAV with a valid header;
Stop completed in 26 ms, and the stopped session survived close/reopen without
renderer errors. There were intentionally no STT segments in this offline test.
macOS Keychain access required owner consent before launch could finish.

Tested ASAR SHA-256:
`6464af0f09243afd210bd25b5a91fb80a841b09d4ddca21f6b72cff8f022c5d9`.
The ZIP checksum is distributed in `SHA256SUMS.txt`. No long-call certification
or fresh cloud latency guarantee is claimed.

## Limits

- macOS Apple Silicon only; unsigned and not notarized.
- System audio requires an explicitly routed input such as BlackHole/Loopback.
- Cloud STT and suggestions require a configured provider key and connectivity.
- Short EN/FR audio checks from the preceding build are documented in the
  [STT report](https://github.com/markoblogo/CoqPi/blob/v0.3.4/docs/audits/2026-10-23/STT_LATENCY.md); they do not prove p95 latency
  on the updated Electron runtime or guarantee interruption-free interviews.
- Finder/mail/calendar backends remain legacy/optional, hidden from the primary
  navigation. Their stored data and external-write approvals are not removed.

## Install

Stop recording and quit CoqPi. Download `CoqPi-0.3.4-arm64.zip` and
`SHA256SUMS.txt`, verify the checksum, extract and replace `CoqPi.app` in
Applications. Local data under `~/Library/Application Support/coqpi` is retained.
macOS may ask to allow the updated app access to Keychain; authorize it locally,
never share the password. Do not bypass security protection globally.
