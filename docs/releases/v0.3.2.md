# CoqPi v0.3.2

This release hardens meeting transcript recovery so a professional call archive
is easier to trust after realtime STT interruption.

## Changes

- Recovered transcript review state now survives close/reopen after Exclude,
  Restore, and Merge.
- Recovery metadata is preserved by backend session sanitization instead of
  being dropped on restore.
- Audio backup manifests can hold both `microphone.wav` and `system.wav`
  sources for the same session.
- Manual recovery can process microphone and system backup sources, label
  system recovery as `OTHER`, and deduplicate by source/hash/chunk.
- A failed STT chunk no longer aborts the whole recovery run; successful chunks
  are kept.
- Transcribe now shows a compact recovery report: recovered, failed, skipped,
  empty, and per-source chunk counts.

## Boundaries

- The default renderer path still starts microphone backup only.
- Real system-audio capture requires a separate routed system stream; CoqPi does
  not infer system audio from the microphone.
- Synthetic tests do not prove real microphone accuracy, system-audio routing,
  or live-call latency.

## Installation

Stop any active recording, quit CoqPi, download the Apple Silicon archive and
`SHA256SUMS.txt`, verify the checksum, extract the archive, and replace the
existing app. Local data remains under `~/Library/Application Support/coqpi`.
